# 回家执行手册（全职转型版）

> **制定日期**：2026-10-12
> **适用对象**：欧仕磊（22 岁 / 大专 / 约 1 年运维经验 / 目标 CI-CD + 云原生）
> **前提**：离职回家，全职学习。家里支持期约 9 个月。生活零开支（奶奶煮饭、父母交水电）。
> **定位**：这不是学习计划，是**约束系统**。内容在学习计划里，这份文件解决的是"人会废掉"的问题。

---

## 零、这份手册为什么存在

《过渡期作战计划》里写过一句最锋利的话：

> **低技术含量的岗位有个隐蔽陷阱：它不会累垮你，它会驯化你。**
> **历史上 90% 的人在这种岗位上废掉，不是因为没时间，是因为没有外部约束。**

**现在情况反过来了。** 你不再是"没时间"，而是"有时间但没约束"。

**这是同一个陷阱的另一个版本，而且更危险——因为你看不见它。**
在职时你时间少，所以不敢浪费；回家后时间多，浪费起来没有痛感。

**所以这份手册的全部内容，就是在替代你在职时天然拥有的那三样东西：**

| 在职时有 | 回家后必须人工制造 |
|---|---|
| 上班时间（硬约束） | 固定作息表（第 1 节） |
| 交付对象（有人看） | GitHub 公开提交 + 两周交付（第 2、3 节） |
| 进度压力（怕被淘汰） | 数据看板 + 退出红线（第 6 节） |

**结论：这份手册里最重要的不是内容，是"每天要做的那几个动作"。**

## 一、每日作息表（硬约束，不可协商）

### 1.1 基础版（建议前 4 周严格执行）

| 时段 | 内容 | 说明 |
|---|---|---|
| 07:00 | 起床 | 不许赖床。起床时间决定全天节奏 |
| 07:00–07:40 | 洗漱 + 早饭 | |
| 07:40–08:00 | **写当日任务包（3 条）** | 见 1.3 |
| 08:00–12:00 | **核心学习块 A（4h）** | 新知识 + 动手，中间休息 2 次各 10 分钟 |
| 12:00–13:30 | 午饭 + 午休 | 午休必须睡，30–40 分钟，否则下午废 |
| 13:30–17:30 | **核心学习块 B（4h）** | 继续动手 / 排错 / 写文档 |
| 17:30–19:00 | 晚饭 + 散步 | 必须离开电脑 |
| 19:00–20:00 | **Shell 每日 1 题** | 不许用 AI，见第 5 节 |
| 20:00–21:00 | **写提交 + 当日复盘（3 行）** | 见 2.2 |
| 21:00–22:30 | 自由 | 游戏、视频、随便 |
| 23:00 | 睡觉 | 固定，不许熬夜 |

**每日有效学习时间：约 9 小时（含 1h Shell）**

### 1.2 三条时间纪律

1. **上午的核心块不许被任何事打断**（包括"查个资料"——记下来，下午再查）
2. **超过 90 分钟必须起身一次**，否则效率断崖
3. **21:00 之后不许学习** —— 你需要一个明确的"下班"信号，否则第 3 周会 burnout

### 1.3 每天早晨写"任务包"（3 条，不超过 3 条）

格式固定，写完贴在显示器上：

```
【日期】2026-XX-XX
1. （今天必须产出的东西）
2. （今天必须产出的东西）
3. （今天必须产出的东西）
验收：晚上用什么证明做完了
```

**为什么限 3 条**：超过 3 条就一定会完不成，完不成就会丧失"打卡感"。**3 条是能保证 100% 完成的上限。**

## 二、GitHub 提交机制（最重要的一条）

### 2.1 为什么这条是核心

**它能把你从"自我监督"换成"社会监督"。**

自我监督靠意志力，意志力会耗尽。
社会监督靠记录，记录不会骗人——**而且断更是公开可见的。**

《过渡期作战计划》里那句话说得很准：

> **公开承诺：在 GitHub 建立公开仓库，每周至少 3 次提交。断更就是公开打脸。**

**现在我们把这个标准提高到：每天至少 1 次提交。**

### 2.2 提交规范（固定格式，照抄）

**Commit message 三段式：**

```
[日期] 模块 - 做了什么

- 具体动作 1
- 具体动作 2

问题：（今天卡在哪，怎么解决的）
```

**实例：**

```
[10-15] Jenkins - 完成凭据管理实验

- 用 jenkins 容器生成 SSH keypair
- 在 Jenkins 添加 SSH Username with private key 凭据
- 用 withCredentials 把凭据注入到流水线

问题：private key 复制时多了一个空行，报 InvalidPrivateKey，
      用 cat -A 检查后发现末尾有 ^M，是 Windows 换行符导致的。
```

**为什么必须写"问题"这一行：**
1. 面试官问"你遇到过什么问题"，你有原始素材
2. 强迫你当天就把问题想清楚，避免"提取消退"
3. 一年后回看，这份记录就是你的简历素材库

### 2.3 提交什么都能算

**不要求每次都是代码。** 以下都算有效提交：
- 学习笔记（md 文件）
- 实验记录（命令 + 输出截图）
- 排错记录（现象 → 排查 → 根因 → 解法）
- 脚本（哪怕只有 3 行）
- README 更新

**唯一的无效提交**："更新"、"修改"、"test" 这种无意义 message。**宁可提交一份 5 行的笔记，也不要写一句废话。**

### 2.4 断更处理

**如果某天真的提交不了**（生病、家里有事），**第二天必须补**，并在 commit 里写明原因。

**连续 3 天断更 = 触发第 6 节的机制检查。**

## 三、两周交付制（防止闭门造车）

### 3.1 机制

**每两周（14 天）必须对外交付一次成品。**"对外"= 发到公开可见的地方（GitHub / 博客 / 社群）。

**为什么必须这么做：**

在家学习最大的风险不是懒，是**"感觉自己学会了"**。没有交付对象，你会不断在"看懂了"和"会用了"之间自我欺骗。

**交付会立刻暴露真相——你能不能给别人讲明白。**

### 3.2 交付清单（照此执行）

| 周次 | 交付物 | 形式 |
|---|---|---|
| 第 2 周末 | Jenkins 流水线全流程说明 | GitHub README + 一篇 800 字笔记 |
| 第 4 周末 | GitLab CI 与 Jenkins 对比 | 一篇 1000 字对比文 |
| 第 6 周末 | K8s 部署 + 滚动更新实录 | GitHub 项目 + 排错记录 |
| 第 8 周末 | 监控栈（Prometheus + Grafana） | 截图 + 配置仓库 |
| 第 10 周末 | **全链路项目整合** | 完整项目 README（这是简历核心） |
| 第 12 周末 | 5 段面试话术定稿 | 写成 md，可背诵 |

### 3.3 交付的最低标准

**一份交付必须包含四要素：**
1. **做了什么**（一段话说清）
2. **怎么做的**（命令/配置，别人能复现）
3. **遇到什么问题**（至少 1 个真实问题）
4. **在真实工作里解决什么**（价值翻译）

**缺任何一条，都不算完成。**

## 四、13 周时间盒（全职压缩版）

> 原计划周期 10/3–1/3。全职后节奏可压缩。以下按**回家日起算**（假设 T 日为回家第一天）。

| 周 | 主题 | 周末必须交付 | 难度 |
|---|---|---|---|
| **W1** | Jenkins 收尾（Day4–7） | 凭据管理 + 推镜像流水线 | ⭐⭐ |
| **W2** | GitLab CI | `.gitlab-ci.yml` 跑通 + 对比话术 | ⭐⭐ |
| **W3** | K8s 部署 | 应用上集群 + 滚动更新/回滚 | ⭐⭐⭐ |
| **W4** | K8s 深化（Service/Ingress/ConfigMap） | 完整 YAML 清单仓库 | ⭐⭐⭐ |
| **W5** | Prometheus + Grafana | 监控栈 + 1 条告警规则 | ⭐⭐⭐ |
| **W6** | 全链路整合 | **一条完整链路 + 完整 README** | ⭐⭐⭐⭐ |
| **W7** | 话术 + 简历三版 | 5 段话术 + 简历定稿 | ⭐ |
| **W8** | 查漏补缺 + 模拟面试 | 自测复盘 + 投递准备 | ⭐⭐ |
| **W9–W26** | **密集投递 + 面试迭代** | **每周至少 3 场面试** | — |

### 关键规则

1. **W8 结束（约 2 个月）必须开始投递，不许再"补一点再投"。**
   **投递本身就是最好的复习**——面试官会精准告诉你缺什么。

2. **每周日晚 30 分钟复盘**：这周交付了什么？卡在哪？下周调整什么？

3. **如果某周落后，砍内容不延时间。** 例如 W4 K8s 深化落后 → 砍掉 Ingress，直接进 W5。
   **时间盒的意义在于到期必须执行。**

## 五、Shell 每日 1 题（运维岗硬门槛）

### 5.1 规则

- **每天 1 题，不许用 AI 查，不许搜答案**
- 卡住 15 分钟就看答案，**但要手抄一遍并注明"这题我不会"**
- 题目来源见 `Week1-Docker自测8题.md` 的同类题，以及后续积累

### 5.2 为什么必须做

你的简历里写了 Shell 脚本 20+，但**自测只有 3.5/8**（提取缺口）。这说明：
**你能照着写，但说不出原理。**

Shell 是运维岗的笔试必考项。**每天 1 题，3 个月就是 90 题，足够覆盖笔试。**

### 5.3 题库框架（自己往里填）

| 类别 | 示例 |
|---|---|
| 文本处理 | awk 统计日志中 IP 出现次数前 10 |
| 流程控制 | 遍历目录，找出 7 天前的文件并打包 |
| 服务管理 | 检测 nginx 进程，挂了就重启并记日志 |
| 磁盘/性能 | 找出占用空间最大的 5 个文件 |
| 定时任务 | 写一个 crontab 每日备份 MySQL |

## 六、数据看板与退出红线

### 6.1 每周数据看板（周日晚填）

| 指标 | 目标 | 实际 |
|---|---|---|
| GitHub 提交天数 | ≥ 6/7 | |
| 交付物 | ≥ 1 件/两周 | |
| Shell 题 | 7 题 | |
| 面试场次（W9 起） | ≥ 3 | |

### 6.2 退出红线（提前定好，避免拖延）

| 触发条件 | 行动 |
|---|---|
| **连续 3 天 GitHub 断更** | 立即自检：是方法问题还是状态问题？调整后重来 |
| **第 4 周复盘，进度 < 60%** | 严肃评估：是计划太满，还是执行出问题 |
| **第 8 周（2 个月）还没开始投递** | 🔴 **强制开始投递**，不许再"准备好再说" |
| **第 5 个月，面试 < 15 场** | 检查简历/话术问题，或扩大投递范围 |
| **第 9 个月，仍未拿 offer** | 按承诺先找一份工作过渡，边干边继续投 |

### 6.3 最重要的一条

> **不要因为"再学一点会更好"就无限期推迟投递。**

**你的计划里已经写明了：不是"学完再找"，而是"学到能面试就开始面"。**
面试官不会考你全部知识，只会围绕简历项目深挖。**你需要的不是 100 个知识点，是一个讲透的项目 + 每模块 3 段话术。**

## 七、家里沟通话术（和妈妈的那通电话）

### 7.1 目标

**不是征求同意（她已同意），而是把"9 个月"变成家庭共识。**

### 7.2 三句话

1. **"我打算离职回来，全力准备到明年 6 月左右开始找工作。"**
   → 明确时间盒

2. **"这段时间我不接零工、不分心，每天按上班的时间学习。"**
   → 明确纪律，让她们知道你不是在家躺着

3. **"到了明年 6 月如果还没成，我会先找一份工作过渡。"**
   → 给出兜底

**第 3 句最关键。父母最怕的不是等待，是"没有终点的等待"。**

### 7.3 关于爸爸

**暂时不用主动说。** 等你走出一段成果再告诉他——那时你手里有证据（GitHub 连续提交、面试记录、offer）。

**顺序反了才是风险：** 在"决定离职"的同时承担"说服父亲"的压力，是给自己加不必要的负担。

## 八、回家第一天要做的 5 件事（不许推迟）

**回家当天/次日，按顺序做完这 5 件：**

1. **建 GitHub 公开仓库 `devops-journey`**（专用于记录转型过程）
2. **提交第一条记录**：把 Week1 + Week2 的成果整理成 README 提上去
3. **写下当天的任务包（3 条）**
4. **做完 1 道 Shell 题**
5. **把本手册打印/存到桌面，每天看**

**为什么第一天最重要：**

因为"先休息几天再开始"这句话，会变成三周。

**第一天的动作决定你后面 9 个月的基调。**
