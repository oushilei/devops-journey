## 三、项目定义：`devops-demo`

**目标**：一条从代码提交到 K8s 部署到监控告警的完整链路。

| 环节 | 技术选型 | 说明 |
|---|---|---|
| 应用 | Go 写的 HTTP 服务（约 30 行） | 编译型，多阶段构建效果最直观 |
| 容器化 | Docker 多阶段构建 | 目标：镜像从 ~800MB 压到 ~15MB |
| 镜像仓库 | 本地 Docker Registry（有余力再上 Harbor） | 先跑通，再优化 |
| 流水线 A | Jenkins Declarative Pipeline | 主学，企业存量最大 |
| 流水线 B | GitLab CI（`.gitlab-ci.yml`） | 对比理解，现代团队主流 |
| 部署 | K8s Deployment + Service + Ingress | 部署到你的 1 主 1 从集群 |
| 监控 | Prometheus + Grafana + Alertmanager | 监控集群 + 应用 |

**最终交付**：一个 GitHub 仓库，含应用代码、Dockerfile、Jenkinsfile、
`.gitlab-ci.yml`、K8s 清单、监控配置、README。

> **README 就是你的作品集。** 面试官会打开它。写清楚：架构图、每步命令、
> 遇到的问题与解决过程、镜像体积优化数据。这份 README 比简历上的三行描述有力得多。

### 2. 内存规划（已确认：16GB）

**确认结论：够用，但必须做取舍。**

| 组件 | 内存需求 | 16GB 下是否可行 |
|---|---|---|
| Windows 主机 | 3-4 GB | 必须 |
| k8s-master VM | 2 GB | 必须 |
| k8s-node1 VM | 2 GB | 必须 |
| Jenkins（Docker 容器） | 1 GB | ✅ 可行 |
| 本地 Docker Registry | 128 MB | ✅ 可行 |
| GitLab CE | 4 GB+ | ❌ 不采用 |
| Harbor | 2 GB+ | ❌ 不采用 |

**已确定的取舍方案：**

1. **Jenkins 本地跑** —— Docker 容器，1GB 够用
2. **GitLab CI 用 gitlab.com 免费账号 + 本地 Runner** —— Runner 约 500MB，
   比本地装 GitLab CE 省 3.5GB
3. **镜像仓库用本地 Docker Registry** —— 不装 Harbor，功能足够学 CI/CD

总占用约 10-11GB，留 5GB 余量。

### 3. 构建机方案（已确认：先用 k8s-node1）

用户选择直接在 k8s-node1 上构建，理由：零搭建成本，当天即可开始。

**已知风险与缓解措施：**

| 风险 | 缓解 |
|---|---|
| 磁盘占用（Go 镜像 + 构建缓存可达数 GB） | 先查 `df -h`；构建后 `docker image prune` |
| 资源争抢影响 coredns | 构建时加 `--cpus=1 --memory=1g` |
| 架构不规范（构建与业务混部） | 先用起来，遇到瓶颈再升级 |

**升级路径**：需要独立工作机时，克隆 k8s-node1，按
`西格玛男人之职业规划.md` B2.5 节修改 machine-id / hostname / IP，再 `kubeadm reset`。

> 这个"先用起来、按需升级"的过程本身是面试素材——能讲出选型权衡比一上来就做对更有说服力。
