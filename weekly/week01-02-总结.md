### 踩过的坑：`nginx:alpine` 在 CentOS 7 上起不来

**现象**：`[crit] "/run/nginx.pid" failed (1: Operation not permitted)`

**排查思路**：先怀疑配置（compose、volume 挂载）→ 用隔离实验排除 → 确认是**镜像与 3.10 老内核的兼容问题**

**解法**：换成 `nginx:1.24-alpine`；或加 `tmpfs: ["/run"]`

**价值**：学会了"隔离变量"这个排障方法 —— 不要一次改多个东西，一次只动一个变量。

### 核心架构：DooD（Docker-outside-of-Docker）

Jenkins 跑在容器里，却要构建 Docker 镜像。做法是把宿主机的 `docker.sock` 挂进容器：

```bash
-v /var/run/docker.sock:/var/run/docker.sock
--group-add 995        # 关键：让容器内的 jenkins 用户有权限读写 socket
```

**为什么需要 `--group-add`**：容器内流水线以 `jenkins` 用户（uid=1000）运行，不是 root。不加这个参数，`docker` 命令会报 `permission denied`。

**技术问答怎么答**：这是 DooD 和 DinD 的核心区别 —— DooD 复用宿主机 daemon（快、省资源、但安全性弱），DinD 在容器内跑独立 daemon（隔离好、但需要特权模式、启动慢）。

### Jenkinsfile 六大语法（全部实机验证）

| 语法 | 验证结果 |
|---|---|
| `agent` | `hostname` 输出容器 ID，证明跑在容器内 |
| `environment` + `params` | `withEnv` 出现；参数生效 |
| `when` | skip 与执行两种情况均验证；`beforeAgent` 不申请节点 |
| `parallel` | **串行 16 秒 vs 并行 5 秒**，缩短约 3 倍 |
| `post` | 实测顺序 `always → changed → success → cleanup` |
| `script` | 作用域坑、`returnStdout`、for/if 控制流全部验证 |

### 踩过的坑（4 个）

**1. 参数在 shell 里取不到值** → 见 README 第 1 个坑

**2. 凭据密码怎么不泄露** —— 三层机制：

| 层 | 机制 |
|---|---|
| 存储 | `credentials.xml` 加密，流水线只引用 ID |
| 注入 | `credentials('id')` 自动生成 `_USR` / `_PSW` 两个变量 |
| 打码 | 日志里出现密码值自动替换成 `****` |

另外用 `--password-stdin` 而不是 `-p`，避免密码进 `~/.bash_history` 和被 `ps` 看到。

**3. 轮询成功但构建失败** → 见 README 第 2 个坑

**4. registry 容器没挂卷，数据在可写层**

排查方式：`docker inspect` 确认旧容器配置 → 发现没有 volume → 重建为命名卷 `registry-data`

**对照实验证据**：
```
删前 curl /v2/_catalog → {"repositories":["devops-demo"]}
重建后 curl /v2/_catalog → {"repositories":[]}
```

## 完整链路

```
开发者 push 代码
      ↓
Jenkins poll SCM 检测到变更（H/5 * * * *）
      ↓
拉代码（git branch: params.BRANCH）
      ↓
docker build（多阶段构建，14.1MB）
      ↓
docker login --password-stdin（凭据来自 Jenkins）
      ↓
docker tag + docker push → 私有 registry（192.168.245.150:5000）
      ↓
curl /v2/_catalog 验证镜像已入库
      ↓
post always: docker logout（清理凭据）
```
